# 变现追踪方法论

## 1. 阶段机

```
S0 想法 → S1 验证 → S2 构建 → S3 上线 → S4 获客 → S5 付费 → S6 稳定收入/规模化
```

| 阶段 | 进入条件（可观察的事实，不是感觉） | 本阶段唯一要回答的问题 |
|---|---|---|
| S0 想法 | 有假设 + 目标人群 | 这东西为谁解决什么问题？ |
| S1 验证 | 有 3-5 个真实潜在用户愿意聊/留下联系方式 | 有人真的痛吗？痛到愿意付出代价吗？ |
| S2 构建 | 有一个能被验证的最小版本定义 | 能不能用最小成本造出来？ |
| S3 上线 | 陌生人可以访问并走完主流程 | 有人会用吗？ |
| S4 获客 | 出现了可重复的获客动作（哪怕只带来 10 个用户） | 用户从哪来？成本多少？ |
| S5 付费 | 收到第一笔真实付款（非亲友） | 有人愿意付钱吗？为什么？ |
| S6 规模化 | 连续 2-3 个月净收入为正且可复现 | 能放大而不崩吗？ |

**阶段必须由 `journal.py stage` 推进，并写明"原因"** —— 阶段轨迹就是案例研究的主线。

## 2. 变现假设的写法

坏：`做个 AI 工具赚钱`
好：
```
假设：东南亚跨境电商卖家（月流水 $5k-50k）愿意为"自动生成多语言客服话术"每月付 $19，
因为现在他们每天要花 1-2 小时人工回复相似的 20 个问题。
验证方式：做一个落地页 + 3 个免费试用名额，7 天内收到 >= 3 个付费意向。
```

一个假设必须包含：**谁 + 什么痛点 + 愿意付多少 + 凭什么这么判断**。

## 3. 假设 → 实验 → 证据闭环

每次尝试都写成 `experiment`：

```markdown
- 假设：把定价从 $29 降到 $9，付费转化会翻倍（收入不变或更高）
- 做法：落地页 A/B，各 500 曝光，7 天
- 成功判据：转化率 >= 2 倍，且收入 >= 原方案
- 结果：转化率 1.1% → 1.9%（1.7 倍），但收入下降 38%
- 结论：价格不是瓶颈，放弃降价；转去验证"谁能一次买年付"
- 状态：done
```

**没有成功判据的实验不是实验，是折腾。**

## 4. 指标分层

| 层 | 例子 | 作用 |
|---|---|---|
| 北极星 | 月度净收入 | 唯一真正重要的结果 |
| 滞后指标 | 付费用户数、复购率、退款率 | 结果确认 |
| 领先指标 | 落地页转化率、试用激活率、咨询量 | 可提前干预 |
| 成本指标 | CAC、服务器费、API 费、时间投入（折算时薪） | 判断是否在烧钱 |

**时间也是成本**：把每天的投入小时数按一个诚实的小时价折算进 `ledger`（`kind=cost, channel=我的时间`），否则永远算不出真实盈亏。

## 5. 单位经济模型（写进 LEDGER-SUMMARY 的解读）

```
净收入 = 收入 - 直接成本 - 时间折算成本
回本周期 = 获客成本 / 月毛利
LTV/CAC  > 3 才算健康（早期可放宽，但必须知道数字）
```

## 6. 成功线与止损线（立项时必须写死）

```markdown
## 成功线（三选一即算变现成功）
- 连续 3 个月净收入 >= $500/月，且不依赖我每天 > 1 小时人工投入
- 或：单笔 >= $2000 的交付合同 x 2
- 或：资产化产品（课程/模板）累计销售额 >= $3000

## 止损线（触发即停止投入）
- 投入累计 >= 200 小时 且 收入 < $100
- 或：连续 60 天无新增付费用户
- 或：成本累计 >= $1500 且无付费验证
```

**为什么要预先写死**：人在投入后会自动美化判断。事先写好的线，是唯一的客观裁判。

## 7. 终局判定表（closeout 时逐条打勾）

| 判定项 | 结论 | 证据 |
|---|---|---|
| 是否达到成功线 | 是/否 | 具体数字 + 日期 |
| 是否触发止损线 | 是/否 | 具体数字 + 日期 |
| 收入是否可复现 | 是/否 | 连续几个月？靠什么？ |
| 是否依赖不可持续的投入 | 是/否 | 每天几小时？ |
| 净额（含时间成本） | 正/负 | ledger 明细 |

**五种终局**：`success` / `failure`（触发止损线主动停止）/ `pivot`（转向）/ `paused`（暂停但可能回来）/ `zombie`（既没死也没长——最难承认，也最该记录）

> 失败的项目同样能产出高价值资产：`为什么失败` 的信息量往往高于成功案例。
