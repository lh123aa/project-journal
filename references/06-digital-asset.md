# 资产化：把过程变成可销售的数字化资产

## 1. 核心认知

**原始日记不是商品，是原料。** 商品是提炼后的结构：

```
原始日记 + 档案 + 数据  →  [publish]  →  案例研究 / 打法手册 / 教训清单 / 数据集
```

买家付钱买的是：**别人踩过的坑 + 真实数字 + 可照做的步骤**。他们不买你的流水账。

## 2. 三层资产（按单价递增）

| 层级 | 形态 | 从哪来 | 单价参考 |
|---|---|---|---|
| L1 单项目案例 | CASE-STUDY.md + LESSONS.md | 一个项目的完整记录 | 低（引流品） |
| L2 方法论手册 | PLAYBOOK.md（跨项目提炼） | 多个项目的 solution 去重合并 | 中 |
| L3 行业数据/榜单 | VAULT-INDEX + 汇总分析 | `vault-index` 跨项目聚合 | 高 |

## 3. 什么值得卖（四条全过才上架）

- [ ] **有真实数字**：收入、成本、转化率、耗时，且带来源
- [ ] **有可复用的决策/打法**：读者能照着做
- [ ] **有坦白的失败**：至少 1-2 个真实的坑及其代价
- [ ] **完全脱敏**：无隐私、无密钥、无客户可识别信息

只有一条不过就继续攒，不要勉强上架——劣质资产会毁掉你后续所有产品的信誉。

## 4. 脱敏流程

1. 维护 `sanitize.txt`：逐条写 `原文 => 替换`，正则用 `re:模式 => 替换`
   ```
   ACME 公司 => A 公司
   re:\b1[3-9]\d{9}\b => [手机号]
   mydomain\.com => example.com
   ```
2. 跑 `journal.py publish`，它同时执行内置的密钥/隐私模式
3. 查看 `_redaction-report.md`：确认替换清单合理
4. **人工通读** `CASE-STUDY.md` 一遍 —— 自动脱敏不能替代人眼（尤其是截图和链接里的信息）
5. 截图先过一遍 `assets/`，模糊化客户名/头像/后台数据

## 5. 商品化外壳（PRODUCT-SHEET.md）

必须写清：
- **谁需要它**：越具体越好（"独立开发者"不如"做东南亚市场的独立开发者"）
- **目录**：让买家 10 秒判断是否相关
- **凭记录说话的卖点**：X 个真实决策 / Y 个真实数字 / Z 条教训
- **定价与授权**：个人学习授权 / 禁止转售；是否含更新
- **免责声明**：结果不构成收益承诺（也保护你自己）

## 6. 定价思路

- 引流品（单案例）：低价或免费换邮箱
- 主力品（打法手册）：按"替买家省下的时间"定价，而不是按篇幅
- 高端品（1v1 咨询 / 定制复盘）：把案例当作品集
- 真实数字越多、越具体、越反直觉 → 溢价能力越强

## 7. 发布渠道（自选）

- 独立站 / Gumroad / Lemon Squeezy（数字商品托管）
- 内容平台做引流：把 LESSONS.md 拆成短内容，指向完整案例
- 社区：目标人群聚集的论坛/Discord（先给价值再卖）
- AI 语料/知识库授权：结构化的 Markdown 本身就适合作为 RAG 语料

## 8. 质量红线

- 不虚构数据、不夸大收益
- 不泄露客户与合作伙伴信息
- 不用别人的项目记录冒充自己的
- 说明数据的时间范围与样本量

## 9. 复查节奏

每完成一个项目：跑一次 publish，把资产包囤起来；每 3-5 个项目：跑 `vault-index`，把重复出现的坑与有效动作提炼成 L2/L3 资产。**积累本身就是护城河。**
